# Alignment診断と再開手順（2026-10-18、実機未実施）

`muhi-session-035`と`036`はAlignmentの60秒タイムアウトで終了。両データに関節履歴はなく、
今回の停止関節は特定できない。今後は`alignment_diagnostics.json`を保存する。

## 実機へ投入できる変更

`record_episode.synchronize_positions()`は起動時、約1秒ごと、完了/停止直前に以下を記録する。

- Leaderの固定目標と現在位置、Follower実測、最後に送った目標
- 関節ごとの目標対実測・送信目標対実測・目標対送信目標の絶対誤差と単位
- 経過秒、周期番号、実測周期、最も遅れている関節、停止理由

端末にも1秒ごとに最大誤差の関節名を表示。元の停止条件（Leader移動3、追従誤差8、
3秒の停滞、1周期0.15の指令変化率）と姿勢合わせ完了条件は維持。
`--alignment-timeout`は60〜120秒、既定60秒。まず60秒で診断し、
実測周期の低下だけが原因と確認した場合に限り120秒を検討する。
120秒設定は接触・機械的干渉への安全性を保証しない。
誤差が3以下のまま収束しない場合は停滞検知が働かず、延長分だけ待つ可能性がある。
物体を支えるなど安全な配置で開始し、強い把持や関節の干渉がある場合は続行しない。

承認後の最初の診断収録（保存先は未使用のパスを選ぶ）：

```bash
conda activate lerobot
cd /path/to/so101-imitation-learning
python scripts/so101_capture/record_episode.py \
  --root "$HOME/workspace/so101-data/muhi-alignment-diagnostic-001" \
  --seconds 40 --num-episodes 1 --countdown 10 \
  --alignment-timeout 60 --gripper-display --gripper-display-hz 4 \
  --task 'Pick up the Muhi bottle and place it into the target container.' \
  --execute
```

## 実機投入を見送る変更

`gripper_lag_model.py`は独立した合成モデルのまま。閉じ目標の先行量を3以内に制限し、
位置誤差と低速を連続して検出すると閉じ目標を一時固定する。ただし位置だけでは
正常な低速追従・物体接触・引っ掛かりを識別できず、合成の極低速例で誤検知した。
目標固定は把持力の解放を意味せず、最後の目標位置へ押し続ける可能性がある。
接触疑いが0.5秒続くと停止し、通信異常はラッチして自動復帰しない。
このモデルは実機ランチャーから呼ばず、`action`/`action_requested`の記録形式も維持する。

## 2026-10-19: 実機診断001の2.022度残差

読み取り専用で`muhi-alignment-diagnostic-001/alignment_diagnostics.json`を解析した。
`wrist_flex`はLeader目標78.197802度、Follower開始75.824176度、約1秒後から
終了まで76.175824度、最終送信目標78.197802度。開始差2.373626度、
終了差2.021978度、送信目標と実測の差も2.021978度。Leader目標は不変。
終了時の他5関節の目標対実測差は最大0.4396（wrist_roll）。
約1122周期/60秒で周期はおよそ51〜56ms。単純な時間不足ではない。

LeRobotローカルのSTS3215解像度4096とDEGREES変換式から、
角度表示の1カウントは360/4095≈0.087912度。2.021978度は約23カウントで、
一つの量子化段差だけでは説明できない。不感帯・摩擦・負荷・機械的干渉の
どれかは位置ログだけで識別できない。

Alignmentだけの`--alignment-tolerance`を追加し、既定2.0、指定上限2.5。
10周期連続で全関節の実測残差がこれを下回り、送信目標とLeader目標の差が
0.2未満という完了条件のうち、前者だけを可変とする。
2.021978度なら明示的な2.5指定で完了する合成テストに成功し、既定2.0では
タイムアウトすることを確認。追従開始時の姿勢差拒否は3超、送信目標の
変化率は1周期1.5、追従誤差停止は8超のまま。
ただし2.5度以下が機械的に安全という証明ではない。腕の干渉や残留負荷が
見える場合は閾値で通さず原因を確認する。
Alignment直後のSAFE_RESETはFollowerの実測位置を保持目標として送り直すため、
残差がある場合はその分だけ直前の目標から戻す。空のグリッパで、腕を支えられる
配置で行い、動作を目視確認する。追従再開には従来の3以内という姿勢差判定と
カウントダウンが残る。追従開始後の指令変化率・追従誤差停止も変更しない。

実機で2.5を試す承認を受けた場合は、上のコマンドに
`--alignment-tolerance 2.5`を追加する。保存先は新しいパスにする。
