## 第1段階：ランチャーの修正

- `--countdown 10`ならCOUNTDOWNに入った周期で10秒を表示し、残り整数秒が変わったときだけ表示する。
  0秒後に `RECORDING STARTED NOW: follow ON, recording ON` を表示する。
- 開始時Leader位置を保存。開始位置からの差、Followerとの姿勢差のいずれかが3を超えればキャンセル。
  回転軸はdegrees、グリッパは0〜100正規化単位。3以下の動きはセンサ揺らぎの許容範囲とする。
  監視周期は20Hz。COUNTDOWN中はFollowerへ指令を送らない。
- capture_config.jsonにcountdown・min_secondsを追記。
- Tracking errorは従来どおり「今回実測−前回送信目標」の絶対値が8超で停止。
  5回転軸の8度、グリッパの8正規化単位を維持する。
- fault_diagnostics.jsonに全軸と該当関節、単位、指令、実測、符号付き/絶対誤差、しきい値、
  モード、経過時間、単調時刻、slew、キュー投入済みフレーム数を記録する。
  last_leader_requestedは最後に読んだLeader値。異常周期のLeaderは読まないためcurrent_leader_requested=null。
  後始末で値が変わる前にメモリへスナップショットし、追従停止・接続終了後、動画保存待ち前にJSONへ出力する。
  強制終了・書込み不能時の保存を保証するものではない。
- 終了経路はSTOPPING→STOPPED。通常操作のSAFE_RESET/TELEOP_RESETを経由しない。
  途中フレームはinterrupted・不採用としてsave_episode/finalizeする。
- 終了時の保持指令は回転軸を取得した現在位置へ設定し、グリッパは直前の送信目標を維持する。
  把持物を落としかねない自動的なグリッパ目標の現在位置への変更を避ける。
  **保持力の安全性は保証できず、前の目標による力が残り得る。** 自動トルクOFFはしない。
  通信異常時は指令成功も保持も保証できない。STOPPED後は監視も終わる。

## 第2段階：合成試験専用の設計と限界

`gripper_contact_model.py`は独立した数値モデル。Session/HardwareIOはimportも呼出しもしない。
CLIで実機に有効化するオプションもない。以下は試験用の仮値で、実機の力・電流から決めた値ではない。

| 項目 | 合成モデルの条件 |
|---|---|
| 閉方向 | 正規化値が減少する方向。今回のデータに合わせた仮定 |
| 接触の疑い | 閉要求中、実測−前目標が3以上、または次目標で差が3以上になる場合 |
| 接触時 | 直前の目標で固定。さらに閉じず、現在位置へも自動変更しない |
| 瞬間的な誤検知 | あり得る。保守的に即固定し、自動で閉じ動作を再開しない |
| 上限 | 誤差絶対値8超で停止要求。接触疑いから0.5秒でも停止要求 |
| 開方向 | 固定目標と前目標の大きい方より1超の開要求が連続2サンプル必要 |
| 開速度 | 最大30単位/秒、1周期の移動最大1.5。閉要求に戻っても自動で閉じ直さない |
| 通信・時間 | 不正値、通信不良、非単調時刻、75ms超の周期間隔で指令生成を拒否 |
| 解除・再開 | 自動再装填なし。接触判定の再開には人による原因確認と新しい試験が必要 |

**固定目標は力制限ではない。** モデルの停止要求は追加指令を止めるだけで、物理的に把持力を除去しない。
0.5秒上限も過負荷防止を保証しない。開く操作は負荷軽減になり得るが、落下リスクがある。
位置だけでは正常把持と引っ掛かりを判定できない。低速でも安全な力を保証できない。
本モデルをランチャーに組み込んでいないのはこのため。
実機採用前に、電流/負荷レジスタの仕様・実値、保護設定、把持力と落下防止、異常後の介入手順を確認する必要がある。
レジスタ値を今回は変更していない。
